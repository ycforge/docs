# AGENTS.md

## Обзор проекта

**docs-site** — статичный сайт документации по библиотеке **@ycforge/yorm** (см. `../yorm`). Собирается на **Diplodoc** (`@diplodoc/cli`, бинарь `yfm`) из YFM-разметки (Yandex Flavored Markdown) в статические HTML-файлы, которые можно разместить на любом HTML-хостинге, GitHub Pages или S3.

Документация ведётся на двух языках: **русском** (`ru/`) и **английском** (`en/`). Содержимое языковых версий должно быть эквивалентным.

## Технологический стек

- **Diplodoc**: `@diplodoc/cli` (devDependency), бинарь `yfm`.
- **Пакетный менеджер**: yarn (v1).
- **Node.js**: ≥ 22.
- **Формат контента**: YFM (`.md`) + `toc.yaml` (навигация) + `.yfm` (конфиг).

## Структура проекта

```
docs-site/
├── AGENTS.md            # этот файл
├── package.json         # скрипты и devDependencies
├── .gitignore
├── .github/
│   └── workflows/       # GitHub Actions: сборка + деплой на GitHub Pages
├── docs/                # входная директория сборки (не содержит .git!)
│   ├── .yfm             # конфиг Diplodoc (build, i18n, vars)
│   ├── presets.yaml
│   ├── logo.png         # логотип (ycforge) в шапке — navigation.logo в toc.yaml
│   ├── en/              # английская версия документации
│   │   ├── toc.yaml
│   │   └── index.md     # и разделы *.md
│   └── ru/              # русская версия документации
│       ├── toc.yaml
│       └── index.md     # и разделы *.md
└── dist/                # результат сборки (не коммитится)
```

Каждый языковой каталог — самостоятельный раздел Diplodoc со своим `toc.yaml`. Имена файлов в `en/` и `ru/` должны совпадать (одинаковая структура разделов), различается только содержимое.

{% note warning %}

**Важно:** `yfm build` копирует входную директорию целиком (кроме `node_modules/**`). Если вход `-i .` — в результат попадает `.git/`, и повторные сборки падают с `EACCES` на read-only объектах git. Поэтому вход сборки — **`./docs`**, а `.git`/`node_modules`/`dist` остаются на уровне репозитория вне входа.

{% endnote %}

## Команды

```bash
yarn install          # установка зависимостей
yarn build            # сборка статического сайта в ./dist
yarn dev              # локальный сервер разработки с hot-reload
yarn build:production # сборка + проверка ссылок
```

Сборка выполняется через `@diplodoc/cli`:

```bash
yarn yfm build -i ./docs -o ./dist
```

## Деплой (GitHub Pages + CD)

- Репозиторий: `github.com/ycforge/ydb-orm-docs`, ветка `main`.
- CD: `.github/workflows/pages.yml` — при пуше в `main` собирает сайт и публикует на `https://ycforge.github.io/ydb-orm-docs/`.
- Пуш — по SSH (`git@github.com:ycforge/ydb-orm-docs.git`): у OAuth-токена нет scope `workflow`, поэтому файлы `.github/workflows/` пушатся только по SSH.

## Стиль и соглашения

- **Язык**: `ru/` — русский, `en/` — английский. Код и идентификаторы в примерах — на английском.
- **Разделы** должны повторяться в обеих версиях: обзор, установка, быстрый старт, Active Record, QueryBuilder, декораторы, шифрование, криптопровайдеры, schema sync, миграции, транзакции, аутентификация, standalone-использование, адаптеры СУБД, валидация, справочник API, разработка.
- **Примеры** кода должны соответствовать реальному API из `../yorm/src/index.ts` (публичный экспорт). При изменении API библиотеки синхронизируйте примеры в документации.
- Применяйте синтаксис YFM: `{% note info %}`, табы `{% list tabs %}`, вкладки кода, `{% cut %}` — для понятной подачи.
- Документация — первоисточник API: не добавляйте несуществующие методы/декораторы.
